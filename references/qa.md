# QA — 出厂前一致性检查

发布前逐项确认。任一不通过，先修再出。

## AirJelly-only 数据边界

- [ ] 当前运行环境可读取 AirJelly profile、memory 与 event；否则已停止生成。
- [ ] 每个成果条目都能追溯至 AirJelly memory / event 标识与日期。
- [ ] 每个条目只使用 AirJelly provenance 支持事实判断。
- [ ] 没有读取 workspace、Git、网页、外部文档、原始应用或其他 MCP 补证。
- [ ] 当前对话只用于确定评测对象、时间窗口、输出用途与公开边界，没有作为成果证据。
- [ ] AirJelly Context 不足时已保留缺口，没有要求用户补材料或启动 fallback。

## 标签与规则

- [ ] 所有负责等级、结果状态取值**都在封闭词表内**，无自创或改措辞。
- [ ] 每个条目的负责等级符合 tie-breaker（取最高；有产出才算「负责」）。
- [ ] 每个条目的结果状态符合 tie-breaker（无证据不升级；合并 ≠ 发布；有数据 ≠ 已验证）。

## 证据

- [ ] 每个条目都有 **AirJelly 来源标识 + 日期**；可用时保留 `source_app` 与 `task_id`。
- [ ] 数字都有来源与日期，近似用「约」。
- [ ] 无编造的数据 / 日期 / 头衔 / 结果。

## 结构与排序

- [ ] 时间线按时间**升序**。
- [ ] 项目线按结果状态**确定性降序**（已交付 → 已产生影响 → 在研发 → 待验证 → 未闭环 → 已停止-归档）。
- [ ] 项目线组标题给出「主责等级」（组内最高）。
- [ ] 使用固定模板，Section、类名、图例与模板一致。
- [ ] 切换控件固定为「① 时间线 / ② 项目线」。

## 命名

- [ ] 页眉与正文**无「绩效评估」「技术评估」字样**。

## 确定性（跨人/跨次）

- [ ] 同一个人、两次运行，产出**结构完全一致**（仅来源数据导致的差异允许）。
- [ ] 换一个人跑，产出的**词表、排序、模板**完全一致。

## 诚实

- [ ] 未验证 / 未闭环项如实标注，未圆成「已完成」。
- [ ] 缺口单列，不隐藏。
