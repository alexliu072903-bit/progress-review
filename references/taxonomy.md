# Taxonomy — 封闭词表与判定规则

标签集**封闭**：只能取下列值，措辞不得改动。冲突时按 tie-breaker 裁定。

## 轴 A · 负责等级（Ownership）

| 值 | 定义 | 判定要点 |
|---|---|---|
| `主导` | 定义目标与方向，对最终结果负责，是主要决策者 | 缺了你，这件事不会发生 |
| `负责` | 独立产出并交付某个模块/环节，对该部分的正确性负责 | 有**直接可归属**的产出物 |
| `推动` | 不直接产出该物，但协调、组织、对齐、解阻塞让事情向前 | 贡献是「让多方动起来」 |
| `影响` | 提供判断/建议/方案，被他人采纳后产生作用 | 不掌控执行 |
| `参与` | 在他人主导的工作中承担部分执行或协作 | 主要产出归属他人 |

**Tie-breaker（固定顺序）：**
1. 取所有成立项中**最高**等级。
2. 「负责」与「推动」同时成立：有直接可归属产出物 → `负责`；否则 → `推动`。
3. 「影响」与「参与」同时成立：其判断被采纳并改变了结果 → `影响`；否则 → `参与`。

## 轴 B · 结果状态（Result State）

| 值 | 定义 | 需要的证据 |
|---|---|---|
| `已交付` | 存在可核验的产出物（merged PR / 上线 / 发布的文档、图、公开仓库 / 交付他人的成品） | 产出物链接或路径 |
| `已产生影响` | 存在可佐证的结果（数据、采纳、反馈、改变了后续行为） | 来源 + 日期 |
| `在研发` | 正在推进，尚未达到可交付 | 进行中的产物或计划 |
| `待验证` | 已有产出但未获得结果 / 未验证 | 产出 + 「尚未验证」说明 |
| `未闭环` | 悬而未决、卡住或待决策 | 卡点说明 |
| `已停止-归档` | 明确不再推进，或被删除 / 否决 | 归档 / 删除记录 |

**Tie-breaker（固定顺序）：**
1. 只认**有证据**的状态；无证据不升级。
2. `已交付` 需产出物；`已产生影响` 需可佐证结果；两者都成立时取 `已产生影响`（更高）。
3. **合并不等于发布**：merged 但未发布 → 记 `待验证` 或 `在研发`，不记 `已交付`。
4. **有数据不等于已验证**：有数据但未形成结论 → `待验证`。
5. 观察结束只选一个结论：扩大 / 调整 / 缩小 / 停止 / 证据不足。

## 排序权重（用于项目线组内排序）

```
已交付(1) → 已产生影响(2) → 在研发(3) → 待验证(4) → 未闭环(5) → 已停止-归档(6)
```

## 主责等级（用于项目线组标题）

取该主题内部所有条目负责等级的**最高值**。
