# Evidence — 证据与「什么算完成」

## 三类陈述，分开写

| 类型 | 例子 | 处理 |
|---|---|---|
| `事实 Fact` | 角色、日期、公开仓库、已发布文档、merged PR | 可直接使用 |
| `判断 Judgment` | 本人的产品取舍、设计动机 | 写明适用范围 |
| `假设 Assumption` | 推断的动机、未确认的影响 | 标为假设，不当作事实 |

## 强制规则

1. **每条条目必须带来源 + 日期**（仓库 / PR / 文档 / 官网 / 截图 / 记忆时间戳）。无来源 → 降级为 `待验证`。
2. **数字**：只留最有说服力的 2–3 个；每个数字必须有来源与日期；近似用「约」。
3. **不编造**：不虚构数据、日期、头衔、结果、用户反馈。

## 什么算完成 / 什么不算

**算完成（可升级到 `已交付`）**：存在可核验的产出物。

**不算完成：**
- 代码已合并但未发布（合并不等于发布）；
- 有数据但未形成结论（有数据不等于已验证）；
- 有人在用、有测试、有发布会；
- 用户忽略/未响应通知（不等于事项完成）。

## 私密与公司内部

- 涉及他人隐私、公司内部数据、未发布功能、内部指标 → **不对外发布**，只做私人盘点。
- 公司产品只展示公开事实与本人负责的抽象范围，不暴露内部数字、路线图、截图。
